# Isolated R2 experiment

**Deferred after live testing.** The user chose to retain the faster relay for
now. This prototype and its reproduction instructions remain for reference;
they are not the active production migration. Worker-owned transfer, OPFS and
completed-file viewing continue in the [relay-first plan](../../docs/architecture-improvement-plan.md).

This is the first Phase 0 implementation slice. It tests a complete R2 object
upload followed by verified receipt into **private browser OPFS**. It is separate
from production rooms, original-byte WebSocket routing, and presentation code.

## Run locally

From the repository root in PowerShell:

```powershell
npm ci
npx playwright install chromium
npm run build
npm run build:pilot
npm run test:benchmark
npm run test:r2
npm run test:pilot

$env:BENCH_MIB = '20'
$env:BENCH_STUDENTS = '2'
$env:BENCH_RUNS = '3'
$env:BENCH_FIXTURE = 'binary'
$env:BENCH_PACKET_KIB = '256'
npm run bench:baseline
npm run bench:r2
```

Use separate sequential runs on an otherwise idle machine. Do not compare a
loaded parallel test run against an idle run. `BENCH_PART_MIB=5|8|16` changes R2
part size; `BENCH_UPLOAD_CONCURRENCY=1..4` bounds simultaneous upload requests.
`BENCH_TIMEOUT_MS` changes the 120-second operation budget. Size is
1–200 MiB, senders 1–30, repetitions 1–10. Large full-classroom cases need enough
memory for the browser's source-file fixtures; the receiver itself uses bounded
8 MiB buffers. The relay benchmark also accepts `BENCH_VIEWER=after` and supports
PDF fixtures when `BENCH_FIXTURE` is omitted.

Reports go to ignored `test-artifacts/`. Local R2 numbers describe emulation on
this machine, not Cloudflare latency, bandwidth, or school-network reachability.

## What is measured

- The relay v2 benchmark starts before selecting files, observes each actual
  persisted-cache completion, then checks original SHA-256 blocks from IndexedDB.
  It reports application cache completion separately from verified readback.
- R2 starts before selection/admission, uploads with bounded concurrency,
  commits the object, closes that sender, then receives into OPFS on a separate
  host page. It checks every 8 MiB source hash, flushes, closes the writer, and
  reads back bounded blocks for verification. No viewer runs and no OS download
  or save picker is used. Admission latency is included; cloud and cache stage
  timings are also reported separately. Revision 2 preloads the receiver worker
  before timing and uses the sender's browser connection for admission.
- The two paths currently use different cache implementations and metadata
  flows. They compare complete candidate pipelines, not isolated R2 versus
  WebSocket network performance. The relay's original first-completion and
  packet-size labeling errors make old v1 reports unsuitable for direct comparison.

This is a happy-path comparison plus API fault tests, not the future production
upload/retry/resume implementation. It does not yet reproduce physical-phone
suspension, campus network failures, traffic shaping, or full room admission
budgets. Hash fixtures are generated by the test runner before timing.

## Live R2 prerequisites

Run Wrangler from the project directory, not `C:\Windows\System32`:

```powershell
Set-Location C:\Projects\flashview
npx wrangler login
```

Enable R2 under **Storage & databases → R2 → Overview** in the Cloudflare
dashboard. After its account setup, create an isolated bucket. Set only the
experiment config's `r2_buckets[0].bucket_name` to that bucket; leave the main
application config unchanged. Review the experiment before a live deployment.

The experiment requires a secret `BENCH_TOKEN` of at least 32 characters for all
owner API requests. It has a separate Worker name and separate SQLite Durable Object
namespace; never use an application bucket or user documents. Create an object
lifecycle backstop for the test prefix and abort abandoned multipart uploads.
The runner deletes known objects, and bounded alarm sweeps catch ordinary late
writes. Initialization failures/unknown writes still need reconciliation; this
is not the production cleanup service or an enforced spending cap.

Once the isolated Worker is configured and deployed, set `BENCH_R2_ORIGIN` to
its HTTPS origin and `BENCH_R2_TOKEN` locally, then run `npm run bench:r2`.
Do not paste tokens into chat or commit them. Live reports omit credentials.
Running the browser on this computer still does not constitute a real campus
or physical-phone test.

An authenticated copy of the original relay is deployed separately using
`benchmarks/relay/wrangler.jsonc`, with its own room namespace and `BENCH_TOKEN`.
Set `BENCH_RELAY_ORIGIN` and `BENCH_RELAY_TOKEN` for `npm run bench:baseline`.
The runner exchanges the token for an HttpOnly cookie so browser WebSockets can
authenticate to this benchmark wrapper. Production room endpoints are unchanged.

## Real-device manual pilot

The R2 experiment now includes a browser host/sender page. Build it with
`npm run build:pilot` before deploying the experiment config. A repository owner
can run `npm run bench:invite` using `BENCH_R2_TOKEN` or the ignored local
`.wrangler/benchmark-secrets.json` to create fresh two-hour invitations. It writes
an ignored `test-artifacts/manual-test-links.html` with both test links. The
global owner token is never embedded in those links or browser assets.

Open the R2 host link on the classroom computer and scan its QR with the phone.
Choose a representative original; keep the phone open until **Upload complete**.
The computer automatically receives and reads back the file in private OPFS,
even after the phone closes. Hashing, upload, and receipt are worker-owned.
Preview only reads an explicitly selected, fully verified local PDF/image.
PPTX preview remains part of the production viewer phase.

Invitations allow ten admissions, 200 MiB per original and 512 MiB aggregate.
Host, sender, original reader and original writer capabilities have separate
permissions and expire with the test. Cloud originals have expiry alarms plus
the bucket lifecycle backstop; verified browser copies remain until removed,
cleared, or evicted. Failed/partial cache receipts are removed. Reloading the
manual host page starts a fresh receipt measurement; production cache-resume
and upload-retry semantics are not implemented here.

For the relay comparison, first open its temporary access link on **both** devices,
then create a room and scan the normal classroom QR. Use the same file/network.
That wrapper requires its own access cookie in addition to ordinary room access.

Both manual pages can explicitly export a JSON report containing file names,
sizes, stage timings and optional network notes, without invitation keys. Upload
and receive times are measured on their respective devices; the manual pilot
does not claim a synchronized cross-device end-to-end time. Its one-second
discovery polling is additional latency outside the displayed receipt duration.
Automated R2 comparisons still include admission, upload, discovery/receipt, and
verification in their overall time. API response `Server-Timing` distinguishes
part authorization, storage/body streaming, and durable receipt; GET diagnostics
measure authorization and storage response headers, not full-body duration.

## Transfer-only pipeline alternative

`BENCH_R2_LAYOUT=segments` enables the comparison required when whole objects
miss the speed gate. It writes checked immutable segment objects and starts
automatic cache receipt during upload. Viewing remains absent and a completed
original is still required before local readiness. This experimental receiver
uses bounded 250 ms metadata polling; reports include metadata and original
request counts. It is not the final notification/scheduling design. Segment
layout requires source SHA-256 per segment, validated by R2. Choosing this option
for a test does not select it for production.

## Current decision status

The upload/cache path and local tests are implemented, and isolated live test
deployments exist. **R2 adoption and tuning are deferred by the user.** If revisited,
acceptance would require comparable speed, connection success, retry/recovery,
and time to all files being verified in private browser cache. Small latency
differences could be accepted for better connectivity; the current regression
was not accepted.
